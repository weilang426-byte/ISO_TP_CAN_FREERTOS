第三次提交:单向通信。
发送队列以及接收队列，
当前三个任务：发送任务，接收任务，显示任务。

发送任务:开启发送中断，以及发送队列一个，同步信号量一个。
每2000ms发送一个CAN报文，任务初始开启中断通知，发送邮箱有数据后进入TX中断，此时关闭中断通知（防止多次进入），然后释放同步信号量。在任务中将CAN报文加入到发送队列中，供显示任务读取。

接收任务:开启RX0接收中断，以及接收队列一个，同步信号量一个。
每1000ms接收一个CAN报文，任务初始开启中断通知，接收函数接收，接收邮箱有数据后进入RX中断，此时关闭中断通知（防止多次进入），然后释放同步信号量。在任务中将CAN报文（成功接收后）加入到接收队列中，供显示任务读取。

显示任务：显示任务分别显示ID和数据。

关闭中断通知的原因：以接收为例，接收邮箱有数据后会进入发送中断，中断中如果只做唤醒接收任务的话，回调函数推出后，FIFO0邮箱还是有数据(取走任务在接收任务)。所以先关闭，等待接收任务将报文取走发送到队列中后下一次接收再开启。

目前CAN底层的收发任务介绍
后续ISO-TP封装好的数据用使用队列传入，队列的长度要小一些。
CAN底层应该只管发送，只讲CAN报文发送出去，不管如何拼接CAN报文，这部分交给ISO-TP层

以单帧为例：

数据：
UDS层将数据打包（最多7字节的数据）交给ISO-TP层；
ISO-TP层发现只有7个字节，单帧SS足够，拼接为8字节的SS（N_PCI和N_Data）交给CAN数据链路层；
结合下面ISO-TP层得到N_AI。

CANID：
UDS层将数据交由ISO-TP层时，同时提供寻址信息：（N_SA、N_TA、N_TAtype=物理寻址），ISO-TP将其封装为N_AI。
ISO-TP层 映射表检测到N_AI对应的CANID，填充CANID，至此CANID加数据（N_PCI和N_Data）都有了
数据链路层将CANID等报文信息封装到TXHeader中，data为8个字节，然后整备后交由CAN物理层。


底层驱动最终CAN物理层发送出该CAN报文。
